SHARED NEXT-ACTION LAYER — SHADOW BUILD

Purpose
A customer attempt, actual connection, appointment and transaction are different objectives. The shared planner turns saved evidence into one proposed obligation with objective, due basis, completion criteria, outcome transitions and red rule conflicts. It does not change priority, first-contact timing, completion suppression, assignment, communication counting or sending.

Canonical source
Cadence lib/next-action/engine.ts and policy.json are canonical. Flow consumes identical pinned copies. contract.json fingerprints the policy, engine and shared UI; each app tests those fingerprints. Run scripts/export-next-action.mjs --check FLOW_APP to verify parity, or --write FLOW_APP after reviewing a canonical change. Both applications must be reviewed and released together when this contract changes. Same evidence and policy produce the same proposal; different/older mirrors can still disagree and are shown for review.

Do not silently fill later-attempt spacing, a reactivation SLA, connection working-hours target or reroute/pause thresholds. They are intentionally unset. Exact verified current-owner calls and explicit working-hours context are required before the planner calculates that interval. No API collector or new time window has been enabled by this change.

Safety and evidence
No-contact restrictions and inactive/recruiting stages precede outreach. Historical rental labels plus renewed intent become classification review, not automatic buyer conversion or exclusion. Original source and incoming time remain intact. Outbound activity, generic last communication, call duration and an old conversation do not prove a new connection. A source two-way timestamp and a broker-reported conversation retain different provenance. Verified note delivery proves receipt, not conversation truth. Explicit skips/holds, customer timing, appointment and contract states are respected. An overdue connection review requires an existing approved clock; the preview never invents a new SLA or automatic reroute. The shadow planner can flag a weekly completion hold that conflicts with an unresolved connection objective while leaving the live hold intact.

Access and deployment
NEXT_PUBLIC_VESTA_NEXT_ACTION_PREVIEW=true is the only display opt-in; unset defaults off. In Flow: My action flow -> Review proposed next actions; selected lead also shows the proposed action. In Cadence: Reports -> Next-action comparison; lead workspace has the same panel. The comparison uses already loaded saved data, renders at most 100 contacts per page and defaults to rule conflicts. It is not a complete new event collection or a new orchestration service. FUB records remain the operational source; no task, message, stage or reassignment is written.
