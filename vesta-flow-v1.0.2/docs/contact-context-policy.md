# Shared contact context release

Source communication evidence has three separate meanings: an outreach attempt, documented customer contact, and current intent. A verified connected-app outcome contributes to the lead's contact history and cadence. It does not grant the API account owner broker performance credit.

The shared deterministic policy retains provider, source record, timestamp, outcome, buyer/seller lane, timeframe and conditional intent. Generic sync notes do not qualify. Recent failed/queued/automated campaign texts do not become broker attempts. Missing direction, invalid/future dates and mismatched person identities do not earn contact credit.

A named approved nurture tag or a documented long-term disposition can reconcile a stale initial CRM stage for the derived cadence. The source stage/tags remain intact. Advanced CRM stages retain precedence. Contradictory or unmapped intent produces a review item. Conditional interest never becomes active simply because a future calendar date arrives. New actual customer engagement is evaluated separately from an integration or broker update.

Applicable consumers:

- Flow queue, customer filters, cadence, explanation and bounded detail reads.
- Cadence normalized spine, governance, local scoring inputs, seller priority, portable overdue reporting and reroute analysis.
- Original Render mirror's derived snapshot and published manager compiler.
- Independent Flow accelerator's targeted refresh, including real calls/texts/notes.
- Independent Cadence Blueprint's prepared reroute compiler and live pre-write contact guard.

Raw CRM records, broker behavior measures, historical first-call latency, source keys, databases and service boundaries remain distinct. App note logging time resolves an open lead obligation but does not certify an on-time broker first-response metric. Existing expert-rating and model-promotion gates remain intact.

No source CRM writes occur while calculating or testing this policy. Deployment uses the existing services with no new cost. Shared parser parity and behavioral fixtures check all compiled consumers; source and consumer deployment order is recorded in the task checkpoint.
