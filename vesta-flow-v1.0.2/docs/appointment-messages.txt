Flow appointment messages — broker workflow

The view consumes the broker's authorized, unsuppressed Flow queue, not the
customer roster. It excludes Zenlist-source duplicates, recruiting and other
non-customer records, conflicting identity/intent, and follow-ups not yet due.
Messaging priority uses original lead creation time, newest first. Matching or
missing creation dates use no recorded conversation, overdue / due cadence,
urgency, lateness and existing Flow priority as tie-breakers. Invalid or future
creation timestamps sort behind valid dates; updated/activity times do not count. An unanswered attempt
is not a recorded conversation. This changes only the messaging view's order.

On selection, one current contact detail request loads FUB evidence. Missing
communication/appointment history or a mismatched ID holds preparation. Current
structured communication outcomes, conditions, cadence stage and available
channel populate the suggestion. Nurture does not default to a fresh inquiry.
Historical conditional intent stays on a permission / wait path.

A message is prepared automatically after evidence and browser history load.
Preparation does not assert consent, approve delivery, or complete an action.
Existing drafts and saved edits survive revisits. Held drafts stay held.

The main screen shows the suggested message, editable wording, channel and:
1. Copy message (after recipient/permission review)
2. Open exact contact in FUB (send there, verify timeline activity)
3. Return to the matching Flow action and sync the actual outcome

Context overrides and provenance are available under Why this suggestion? /
Adjust context. Training feedback is under Hold for model review. Simulation
controls and the full research chart are removed from the broker's main screen;
the pure simulation engine remains covered by its tests.

Automatic transport is disabled pending FUB access. No queue, cadence, daily goal,
FUB data, sending provider, Render configuration or production model is changed
by generating, editing, copying or holding a draft. Existing Done sync behavior
is reused from My action flow and never sends the copied message again.

Review history and held feedback remain browser-local with export available.
Cross-device deduplication and central training storage are not implemented.
